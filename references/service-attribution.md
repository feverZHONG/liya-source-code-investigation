# 线上服务溯源（只有运行中的站点／服务，没有源码）

> 场景：有人甩来一个民间站点／私服／社区服／自建 API，**没有公开仓库**，要弄清「谁在运营、什么技术栈、跟哪个开源项目同源」。
> 产物＝一张指纹表 ＋ 一行明确写出「服务器侧拿不到的」——用户手上的一手线索（群主、管理员、文件上传者）正好补那几格，两头一对才锁得住人。
> 用户说「细究这条链接／核心是这个域名」时，要的是**链接背后的可验证标识物**（注册时间、账号 uid、消息时间戳、协议/框架指纹）。头像、昵称一类图像素材只算佐证，别把佐证当结论交上去。

**先跑工具（一条命令出七步里的前六步）**：

```bash
bin/srvrecon <domain> --ports 22,80,443,18080,30400 --out <目录>      # 报告.md ＋ recon.json
bin/srvrecon <domain> --fetch --out <目录>                            # 另存首页与 js/css 的 sha256 清单
```

输出：DNS 全记录／域名与 IP 的 RDAP／**CT 多源（certspotter ＋ crt.sh，各自如实记错）**／端口面（开・拒・无响应三分）／HTTP(S)（含 `Server: Proxy-*` 代理污染告警）。**工具只做被动 GET、零副作用**；产物拿回本文件继续人工下钻（协议指纹、门禁流程、分发渠道、举报备料）。
自检：响应头若出现 `Proxy-*`，本次基础设施归属结论作废，换网络直连复测——**代理污染是这一类活最常见的假结论来源**。

## ① 先验传输层：http 还是 https

```bash
curl -sS -m 15 -I https://<host>/ ; echo "exit=$?"      # Connection refused/timeout = 没有 TLS
curl -sS -m 20 -L -o page.html -w '%{http_code} %{size_download}\n' http://<host>/
```

- **只有 HTTP 的站点在浏览器里会被强制升到 HTTPS → 白屏／打不开**，用户侧的表述是「这个网址挑浏览器」。别当站点故障，先实测端口再下结论。
- 端口 80 通、443 不通，说明是自建自管，不是云托管成品。

## ② 整包拉前端，读它的注释

拉首页 ＋ `assets/js/config.js` 类配置 ＋ 每个功能页（注册／教程／反馈／绑定）。

- **config.js 是金矿**：群号、网盘直链、版本号、FAQ 原文、`news` 数组（＝带日期的运营大事记，能直接还原站内时间线），信息密度比首页 HTML 高一个量级。
- **页内开发注释是最高价值身份材料**：作者自己写下的「原实现用了 async/await，这在老浏览器里是语法错误」「线上日志证明请求确实发出去了」这类话，等于自述工作方式（会写码、看线上日志、按用户反馈迭代）。
- 顺手判「有没有公开仓库／联系方式」：
  ```bash
  grep -inE 'github|gitee|仓库|开源|联系|邮箱|服主|维护者' *.js *.html
  ```
  **零命中本身就是结论**（对照：开源项目 README 一般第一屏就挂仓库链接）。
- **FAQ／免责声明要跟站内实际行为对照读**：一边声明「社区自建、非官方、非盈利、**不提供任何官方游戏资产**」，一边在下载中心挂着客户端与资源包的网盘链接——**这种自相矛盾本身就是结论**（民间服免责模板的标准写法：资产不是我提供的，我只是恰好知道它在哪）。用户会拿这类句子当「很好笑的点」递过来，要的是把矛盾点出来，不是复述原文。
- **公告「全量」怎么算得起**：站内公告常是 **JS 渲染**（首页只有一个空容器，条目录在 `assets/js/config.js` 的配置对象里）⇒ 取全量＝把那个数组整个读下来；再探一把常见公告接口（`/api/news`、`/robots.txt`、`/sitemap.xml` 之类）全 404，就能把「没有别的公告来源」写成一句实证，而不是「我看到的就这些」。
- ⚠️ **公告日期是运营方自述，不是时间线**：实测公告里「欢迎加入交流群」的日期**早于**群资料记录的建群日 ⇒ 多半是事后补写。写法：自述最早动作记「**运营方自述起点**」，**时间线一律以实测（群建立／域名注册／证书签发）为准**；两者不一致时并列摆出，别拿自述去覆盖实测。（对照 ⑤「注册时间常与站内公告同天」——那是可以互为旁证的同向巧合，不是反过来拿公告定时点。）

## ③ 解析 IP、探服务端口

```bash
getent hosts <host>                            # 拿 IP
curl -sS 'https://ipinfo.io/<ip>/json'         # 归属国家／ASN／机房
curl -sS 'http://ip-api.com/json/<ip>?lang=zh-CN'
for p in 80 443 18080 30400 8080 3000; do timeout 3 bash -c "echo > /dev/tcp/<ip>/$p" 2>/dev/null && echo "$p OPEN" || echo "$p closed"; done
```

- 游戏／后端服务常把**列表服务＋网关**这一对端口留在公网。这两个口就是协议指纹的入口。
- **端口清单别靠常识猜——去「疑似上游实现」自己的配置里取**：clone 过的仓库里一般有 `config/default.json` 之类的默认端口定义（实测「列表服务 18080 ＋ 网关 30400」就是从上游配置里读出来的），拿这几个号逐个打对方；打中就是协议指纹的入口，也顺手验证了「客户端为什么能不改协议直连」。
- **再扫一小把常见服务端口**（22/21/3306/6379/5432/27017/3389/9000/9090/8081/8088/5000）：SSH 开＝管理入口暴露（也是攻击面）、数据库口开＝运维问题；**只探通断**（`timeout 3 bash -c 'echo > /dev/tcp/<ip>/$p'`），不连接、不尝试登录。命中与全闭都要落笔——「除 SSH 外全闭」本身就是一条可写结论。
- 只探公开端口、只读；不做口令尝试、不做爆破。

## ③·5 DNS 层：谁在管解析、有没有正经业务、同族域名

本机解析器常常只认得被查的那个 host，查别的域回 `Could not resolve host` → **DNS 查询走 DoH**：

```bash
curl -sS 'https://dns.alidns.com/resolve?name=<domain>&type=NS'      # 阿里 DoH，国内网络可达
curl -sS -H 'accept: application/dns-json' 'https://cloudflare-dns.com/dns-query?name=<domain>&type=A'
```

- **NS 记录＝「谁在管解析」**：`*.ns.cloudflare.com`＝Cloudflare 托管，`dns*.hichina.com`＝阿里云 DNS。和注册商放一起看，能判运营者的工具栈是不是一套。
- **A 记录直接给出源站 IP ⇒ 代理/CDN 是关的**（开了代理 A 会是 CDN 自己的 IP 段）。结论要点明「域名在 X 管解析」与「走了 X 的防护」是两件事。
- **MX 记录判这个域名有没有正经业务**：`mxbiz*.qq.com`＝腾讯企业邮箱 ⇒ 不是随手囤的域名。SOA 的 serial 只是 zone 版本号，**不是注册时间**，别拿它当上线时点。
- **顺手扫同族域名与常见子域**（同名换 TLD ＋ `www/api/cdn/m/mail/admin`）：常能翻出运营者的其他资产（实测翻出过一套需登录态的 `api.` 接口、一个指向对象存储桶的 `cdn.`）。
- ⚠️ **同族域名只是旁证**：同名 ＋ 同 DNS/注册商体系 ≠ 同一人。坐实主体得看备案/实名信息（查法见 ⑤），查不到就在档案里写「旁证／未证」，别在结论里合并成一个人。

## ④ 协议指纹：拿已知开源实现当标尺（最硬的一手）

社区里传「这服用的是 X 的开源方案」时，别信传言、也别只看端口号相同：

1. 翻出你手上已有的 X 源码（`cache/` 里的 clone），定位它的服务端路由与响应结构：
   ```bash
   grep -rn 'createServer\|pathname ===\|pathname.startsWith' <repo>/src --include='*.ts' | head -40
   ```
2. 打对方同名端点，**逐字段比对 JSON 形状**（字段集 ＋ 嵌套顺序 ＋ 边界值），不是只看「能通」：
   ```bash
   curl -sS -m 12 -w '\n[%{http_code} ct=%{content_type}]\n' http://<ip>:<port>/serverlist
   ```
   形状一致 ⇒ **协议同构**（客户端不改就能连）。
3. 再**找反证判是否代码同源**：
   - 开源版有的端点对方 404／结构不同（例：开源版 `/health` 返 `{ok,startedAt,uptimeSeconds}`，对方没有）
   - **后端框架报错原文（白送的技术栈指纹，多打两个路径就能收一套）**：往 `/api/*` 发空 body／非法 JSON／不存在的控制器，读返回串——
     - `The input does not contain any JSON tokens. Expected the input to start with a valid JSON token… LineNumber: 0 | BytePositionInLine: 0` ⇒ **System.Text.Json（ASP.NET Core／.NET）**
     - `controller not exists:app\api\controller\<Name>` ＋ 中文错误页「系统发生错误」⇒ **ThinkPHP（PHP）**，还顺带吐出路由命名空间结构
     - 顺手判「两个端口是不是同一个进程」：同一响应体＋同一静态处理器 ＝ 一个进程既发站点又发接口（自建服务常见）。
   - **HEAD 不可信**：自建服务常不实现 HEAD（回 404 或空体、`Content-Length: 2`），想读响应头／`Last-Modified` 一律用 `GET -D -`；拿 HEAD 的空结果判「文件不存在／没有这个端点」是误判。

> **铁律：协议同构 ≠ 代码同源。** 结论必须分开写——「协议沿用了谁」和「实现是自己写的」是两句，合成一句「就是 X 的服」就是错的。

## ④·5 证书透明日志：子域名 ＋「曾配过 HTTPS」

```bash
curl -sS 'https://api.certspotter.com/v1/issuances?domain=<domain>&include_subdomains=true&expand=dns_names'
```

- 给出**签发过证书的全部域名／子域 ＋ `not_before`/`not_after`**：现在 443 关着，也能证明某天确实配过 HTTPS，而**证书签发日常与站点上线节点同天**。
- `*.domain` 与裸域同时出现＝当时是按整域签的。
- **CT 至少两个源交叉，且「查不到」只能写成「该源查不到」**：crt.sh 常态 502／限流（本机复测同样 502），certspotter 是稳定的替代入口。据单一源的空白下「该域名没有证书日志」的结论是**错**的——实测换源即得三张证书；这类空白结论还会被人（同伴 AI／外部评审）当事实接着用，必须当场复核。
- **同一域名多张证书＝一条时间线，不是「配过一次」**：不同 CA 在不同日期各签一张（实测开张日一张 LE、十天后又两张 DV），说明**有人在反复折腾 TLS 配置**；与前端带日期的修复注释合看，结论是「站点至今在迭代」。而现在 443 拒绝连接 ⇒ 定性是**「配过又撤」**，不是「从没配过」——这个差别直接影响风险叙述与举报口径。
- 实测反哺档案：这种「第三个源／第三份报告」的复核常**反过来查出自己档案的漏记**（本档此前只记了一张证书）。按 SKILL.md ⑥ 的留痕规矩落一条 ⚠️ 修正注，别静默改。

## ⑤ 域名注册信息（`whois` 可能没装，直接走 RDAP）

```bash
curl -sS -H 'Accept: application/rdap+json' https://rdap.nic.ink/domain/<domain>                        # .ink 注册局
curl -sS -H 'Accept: application/rdap+json' https://rdap.identitydigital.services/rdap/domain/<domain>
curl -sS -L -H 'Accept: application/rdap+json' https://rdap.org/domain/<domain>                         # 302，必须 -L
```

- 取：**注册时间**（＝站点上线的硬时点，常与站内公告同天）、注册商、到期日、末次变更。
- registrant 通常只留国家／省级（实名打码）；拿不到名字就写「未获取」，别推。
- **国内主体（备案）另走备案查询，且必须多源**：`icp.chinaz.com/<domain>`、`icp.aizhan.com/<domain>/`（后者还带「按主办单位反查域名」入口）。⚠️ 这类站多是 **JS 渲染**：抓到的「暂无数据／加载中」只是占位文本，**不是查询结果**——拿它写「未备案」就是错结论（实测同一域名一个源渲染出完整企业表、另一个源只回占位）。至少两源交叉，且「查不到」只写「该源查不到」。
- **反查主体名下的域名要用「渲染后取正文」的方式抓**：`icp.aizhan.com/reverse-icp/?q=<主办单位全称>&t=company&o=domain`（直接 curl 常拿不到表，走 `web_extract`／渲染抓取）。用途是**排掉一类假设**：主体名下若只有一两个域名，「同名只是行业命名习惯／这公司有一堆游戏域名」这条解释就不成立 ⇒ 「同名不同主」再加一档。反查读数是**第三方聚合站（单源）**，写「第三方读数」，**不进对外材料当硬证据**；要硬化得回工信部／工商原始渠道。
- **备案主体 ≠ 域名注册人，两条只能并列不能合并**：备案记的是「谁在中国境内提供网站服务」（常是企业），registrant 记的是域名实名（常是个人、只到省级）。同名不同 TLD 尤其要小心——实测一方是十年前注册、企业备案的老域名（主站已下线、只剩 `api.`/`cdn.` 子域在跑），另一方是当月注册、实名个人的新域名 ⇒ 结论写「**同名不同主（待核）**」，只因同名就归并＝错。
- `www`／裸域无 A 记录而子域有 ⇒ 该域只当后端／CDN 在用（主站早已下线）；这一条能解释「为什么它的 api 活着但首页打不开」。

## ⑥ 「有没有仓库」怎么答得硬

- GitHub：先 `/search/repositories?q=<关键词>`，再用 **code search 搜域名字符串** `/search/code?q="<domain.tld>"`（**必须带 token**：`-H "Authorization: Bearer $GITHUB_TOKEN"`）——这是找「谁把这个域名写进过代码」的唯一好用入口。
- **Gitee API 未登录时对任何关键词都返回 `[]`**（实测 `spring` 也是空）⇒ 空结果**不能**当作「Gitee 上没有」。要下结论得换通道（网页／通用搜索）或标注未验证。
- 反向 IP 查询服务常回 `No DNS A records found`（共享／新 IP 尤甚）——拿不到就写未获取，不要把它写成「该 IP 上没有别的站点」。
- 结论三件套：① 仓库／代码搜索有没有命中 ② 站内有没有仓库链接 ③ 技术栈指纹是否吻合（例：.NET 自研 ＋ 门禁分发 ＋ 只走群文件/网盘 ⇒ 「闭源运营服，不是开源项目」站得住）。
- ⚠️ **判「停更」看 `pushed_at`，不看 `updated_at`**：`updated_at` 会被 star／issue／元数据活动刷新（实测某仓库 `updated_at` 停在 10-08、`pushed_at` 却停在 08-30）。用 `updated_at` 写「近日还在维护」＝错。
- ⚠️ **判「有没有预编译包」看 Releases**（`/repos/<owner>/<repo>/releases`）：实测上游 Releases=0 ⇒ **不存在"他放出来的 APK"**；下游那个带他包名的客户端只能是**源码构建或群内流传的构建**，来源别写成"上游发布包"。
- **端口／路径沿用上游时，先把上游 README 读进来**：客户端连的端口、取配置的路径若与上游文档逐字对得上（实测：`0.0.0.0:18080`／`30400`／`127.0.0.1:18080`），「技术继承」就从"同构"升格成**有文献出处的继承**——一句话能省掉一堆推断。

## ⑦ 素材与素材元数据

站点图直接从 wiki／老资源搬的，PNG 里会留痕（`Software: Adobe ImageReady`、`date:create` 是很多年前）——用来判「素材是搬的还是自制的」，也常能反推素材出处（站内一般自注「立绘来源：XX wiki」）。

```bash
python3 -c "
import struct
d=open('x.png','rb').read(); i=8
while i<len(d):
    ln=struct.unpack('>I',d[i:i+4])[0]; typ=d[i+4:i+8].decode('latin1')
    print(typ, ln, d[i+8:i+8+ln][:120] if typ in ('tEXt','iTXt','zTXt') else '')
    i+=12+ln
    if typ=='IEND': break
"
```

**元数据不只是「自制 vs 搬来」，还能给素材分批**：把站内同类素材（图鉴／卡面全套）逐张读完元数据后按 `date:create` 聚合——同一批导出的时间戳会挤在一起（实测 9 张落在同一分钟内、同一 `Software`）⇒ 记「**同一批官方导出**」；**尺寸与元数据同时分家**的那几张（分辨率不同、且零元数据）与其余不是同一次导出 ⇒ 单列一组。

⚠️ **站内的素材出处自注只覆盖它自己说的那部分**：站内写「立绘来源：XX wiki」解释不了另一组（尺寸不同、零元数据）的来源 ⇒ 那组记「**来源待核**」，**不写「自绘」也不写「扒的」**——本轮证据只到「不是同一批导出」。

**判「图标／立绘里画的是谁」：拿官方素材当标尺，别让模型自己点名。**

- 官方卡面立绘可从 bwiki 类站点白拿（MediaWiki API，三步免登录）：
  ```bash
  curl -sS "https://wiki.biligame.com/<wiki>/api.php?action=query&list=search&format=json&srlimit=10&srsearch=<角色名或卡面名>"   # ① 找词条
  curl -sS "https://wiki.biligame.com/<wiki>/api.php?action=parse&prop=images&format=json&page=<词条>"                          # ② 词条挂了哪些图（挑「XX立绘.png」）
  curl -sS "https://wiki.biligame.com/<wiki>/api.php?action=query&prop=imageinfo&iiprop=url|size&format=json&titles=File:<立绘文件名>"  # ③ 拿 CDN 直链
  ```
- **拼一张并排图再问一次**（PIL 横向拼：官方图标／待判图／官方立绘，各带编号，再 `vision_analyze`）：单张问「这是谁」模型爱猜角色名；并排问「哪两张是同一角色」它会被迫逐项比特征（瞳色／发带／发饰／领口），结论才可用。
- **判据落在可核特征上**（瞳色、发饰、发带、挑染位置），不落在「像谁」。用户给的判读与自己比对的结果不一致时，**记「归属待核」并保留两种候选，不单方面改判**（改判要留痕，见 SKILL.md ⑥）。
- **官方渠道版图标＝天然的标尺**：带周年角标／渠道角标的那版是官方的；拿它跟待判图一比，「这个自制图标连角色都不是官方的」这类结论一眼就出来。

## ⑧ 分发渠道溯源：客户端／资源包是从哪发的

民间服／魔改包的客户端与资源包基本不放官网，走**网盘 ＋ QQ 群文件**——网盘这条能读出运营者信息：

```bash
curl -sS -m 25 -L -A '<桌面UA>' -o pan.html 'https://pan.baidu.com/s/<surl>?pwd=<pwd>'
```

带 `pwd` 的分享链，页面初始化 JSON 里**无登录可读**：`share_uk`（分享者百度账号 uid）、`shareid`、`linkusername`（网盘昵称，中间字常打码）、`share_photo`（头像，可直接下载）、`owner_vip_level`。

- **网盘昵称＝该百度账号昵称**（百度系通用）→ 可直接拿去百度／贴吧检索同名人，常比 QQ 号好查。
- 校验分享密码：`POST /share/verify?surl=<surl>&t=<ts>&channel=chunlei&web=1&app_id=250528&clienttype=0` ＋ body `pwd=<pwd>`，回 `errno:0` 即通过；`/share/list` 列文件仍需登录态，取不到就写「未获取」。
- **分享创建时间也是无登录可读的**：`GET /share/wxlist?channel=weixin&version=2.2.2&clienttype=25&web=1&uk=<share_uk>&shareid=<shareid>&page=1&num=100` 会回 `link_ctime`（秒级时间戳）＋ `uname`／`uk`（可与 init 页字段互校）。用它判「这个分发口挂了多久」——实测与站点开测同日、此后未换 ⇒ 分发口从第一天挂到现在。目录接口走这条会回 `errno:-130`（风控／需登录），`/share/list` 回 `errno:2`，都属正常，写「未获取」即可，别反复试。
- **QQ 群文件这条拿不到**（无接口）——那半格只能靠用户：谁是群主/管理员、谁上传的。

## ⑨ QQ 生态的两条链（收藏分享卡、公开头像）

群里转的「QQ收藏」卡片（`https://sharechain.qq.com/<32位key>`，表现为「笔记 <域名>」）是一条被忽视的一手链：

```bash
curl -sS -m 30 -L -A 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120 Safari/537.36' \
  -o sc.html 'https://sharechain.qq.com/<key>'
```

- **手机 UA 只给正文＋时间；桌面 UA 的页面 HTML 里直接内嵌 `window.syncData`**——无登录、无鉴权，整条收藏的元数据全在里面：
  - `share_nick_name` / `share_uin_security`：分享者（收藏这条的人）昵称／加密 uin
  - `collection.author`＝**原始出处**：`group_name`（群名）、`group_id`（群号）、`num_id`（**发布者 QQ 号**）、`str_id`（该 QQ 的群昵称）
  - `collection.create_time`（原始消息时间）／`collect_time`（收藏时间）／`shareData.create_time`（分享链生成时间）／`view_cnt`
  - `html_content`＝收藏正文原文
- 时间戳单位要看位数：`collection.*` 里 13 位的是毫秒，`shareData.create_time` 是秒。
- 头像：`share_head_image_url`（带 `k=` 键，分享者头像）；**`https://thirdqq.qlogo.cn/g?b=qq&nk=<QQ号>&s=640` 不带键也能取任意 QQ 的公开头像**。QQ 昵称接口（`users.qzone.qq.com/fcg-bin/cgi_get_portrait.fcg`）**需登录**，明文昵称拿不到就写「未获取」。
- 价值：一张转发卡片就能还原「谁在哪个群首发 → 谁收藏 → 谁转出来」，比问人快一步；图像素材（头像）只是佐证，别当结论。

**QQ 群分享链**（`qun.qq.com/universal-share/share?...&busi_data=<base64>`）同样白送元数据，`busi_data` 解 base64 就是 JSON：`{groupCode, token, uin}`。

- ⚠️ **`uin` 是「生成这条链接的人」，不是群主、也不是目标人物**——把链接交到手上的往往就是这个人本身，先核对再入档（实测：把它当第三方号码报上去，当场被用户更正「就是我」）。分享链类字段一律先问一句「这个字段的主人是谁、谁手里会有这条链」。
- 群资料页截图（用户截图）是可读的一手材料：**人数／建群时间／公告（常写着分群号）／群文件与群相册的「近七日 +N」／群精华条数**。近七日增量指向**分发口正在使用**（群文件新增＝客户端/资源包就在那批文件里），建群日则常与域名注册、公告改版同天 ⇒ 合入「开张日」时间线（见 ⑩）。

## ⑨·5 门禁类站点：注册／准入流程本身就是证据

民间服／社区服爱拿「答题注册 ＋ 绑群」当滤网。把这条流程拆开，能同时拿到**技术指纹**与**运营者画像**：

1. **先判「哪个动词消耗配额」**——反复打取题接口（`GET /api/quiz` 类）读回执里的 `remaining`：**数值不变 ⇒ GET 免配额，可任意枚举**（实测 25 连取恒为 5；同一个数在提交接口打一次就 5→4）。于是「每批随机 5 题」的题库能被几十次 GET 穷举干净（48 题题库实测取满）。
2. **提交接口只回对错、不回正确答案，是设计而不是「拿不到」**——前端注释里作者常自己写明理由（乱答一次就骗到答案，十几次刷穿题库）。结论写「服务端不回传答案」。
3. **票据语义**（`passToken` 类）：通过后发一次性票据；**「用户名被占用」这类失败不消费票据** ⇒ 改名可重试、不必重答；票据过期回 `needQuiz` 类标记，前端退回答题步。这些全在前端 JS 里逐行写着。
4. **题库难度 ≠ 出题人资历，别拿题面推身份**（已改判）：题目全是中后期细节与圈内黑话时，第一反应会是「出题人是从头玩到尾的老玩家」——但 **LLM 生成的题面同样能模仿深度**（拿 wiki／攻略喂一遍就出一套）。判据必须加反向对照：① 逐题读可疑／自相矛盾项（离谱数值、把玩家梗当官方设定、指向不存在的角色／遗漏主要角色）② **圈内人一句「这题目一眼有问题」＝高质量反证**，收到先复核、再改判。⇒ 结论只能写「题库疑似 AI 生成／人肉出题」二选一并标待核；真正能推身份的是编码痕迹、运营动作、群控关系这类硬指纹（与 SKILL.md「完成度 ≠ 作者懂机制」同族错误：**内容深度 ≠ 人肉深度**）。
   复核题面的正路：**拿每题的实体去数据源检索**（角色名／圈内黑话／数值／联动名），把题分成三类——① 前提成立（题面怪但真实）② **口径浮动**（答案随版本／活动／统计口径变）③ 纯黑话（公开数据源查无此词）。实测多数落在 ②③：这时**结论写性质**（「口径漂浮 ＋ 黑话门槛」），**不要写成「题目有错」**——两者的举证责任与后续动作完全不同。

    ⚠️ **但「先写性质」不等于「永远不写错」**：把核不动的题**一次性编号成表**交委托方（他能一口气答十几条），他逐题拍定之后，错就是实锤——改写「据委托方确认」并落成错型表，别还挂着「口径浮动」。实测六类，逐题对号即可复查：
   - **照抄被推翻的官方措辞**：官方原话后来被考据否掉，出题人照搬当死答案（「唯一一位……」）
   - **把对话里的对立面当答案**：A 的正确特征被安到常与 A 争辩的 B 头上
   - **两人写成一人**：题干用单数问「担当是谁」，设定里其实是两个人
   - **专名随手换字**：同一人/物在题库里两种写法，或把甲叫成乙
   - **前提或量词错**：「除 X 以外」而 X 其实有；「弄几个」实为「弄几组」
   - **无唯一解**：「一共有多少位」取决于统计口径（可玩人数／联动／NPC 分池）
   ⇒ 这类门禁的成色一句话就够：**它考检索，不考理解；挡得住懒人，挡不住陌生人。**
5. **运营活跃度不看公告、看代码**：前端注释里带日期的修复说明（「某日修『点了没反应』」「线上日志证明请求确实发出去了」）常比站内公告新一周以上 ⇒ 运营是活的，且这人自己看线上日志。
6. **准入链＝三级串联**：`群成员身份 → 账号（答题＋绑定）→ 进服`，任一环断则进不去；服务端能判「某 QQ 在不在该群」⇒ **运营方手里有一个能读群成员名单的东西，身份位置至少是群管理级**。⚠️ **门禁的边界要写清**：站内公告写着「关闭游戏内自助注册」，而群内同期仍在教「进游戏后点右下角输账号建号」——若该路径仍有效，则**门禁拦的是官网注册这条道，不是唯一入口**。这类「公告 vs 实际」的矛盾按待核写，别直接判「门禁无效」。
7. **「改个名字就能解锁」＝客户端遗留调试开关的实证**：圈内流传的操作（「左上角把名字改成某口令 → 解锁卡面／体力／等级」）说明**客户端里仍带着调试／白名单分支**，而这类口令靠的是客户端本地判定；它常与「AI 发现的那大漏洞＝调试开关发布出去」互为印证，也解释了离线化为何可行。同一条还给出第二个结论：客户端可信（不用反作弊）⇒ **门禁只筛身份、不约束行为**，改数据／开挂照样能做。两件事一起写进结论：**控人不控数据**。
8. **用户问「能不能扒出答案」＝两问两答**：① **站点侧**——先探静态泄露（题库文件的常见变体路径 `/questions.json`、`/data/`、`/assets/`、`/config/`、`/static/`、`/wwwroot/`、`/api/questions` 等一把打完，实测全 404 ⇒ 文件在服务端不在 web 目录），再核接口语义（取题只给题面、判卷只回对错）⇒ 结论是「**服务端侧无答案泄露，只剩提交穷举，且被按 IP 配额挡着**」，别把它写成「拿不到」；② **公开资料侧**——题库本身若是从公开 wiki 字段拼的（见 ⑫ 的查重口径），答案对会查资料的人就是**半开卷** ⇒ 结论写「门禁强度 ＝ 你愿不愿意花十分钟查资料」，比「答案泄露」更能说明成色。**边界（明确写进交付）**：**不产出整卷答案表**——那是绕过门禁的工具、不是判断材料；逐题给出处页可以，成卷不给；也不要拿答案去注册建号。
9. **枚举出来的题库／清单要「另存成可复测快照」，别埋在链路文档里** —— 闸门拆解完，题库这类**可复用资产**从案卷正文里筛出来独立存放，四步：
   - **回源头重取，别从旧档转录**：旧档按列表顺序记的题面，**列表序号 ≠ 接口 id**（两回事，转录会把隐含的编号关系一起固化错）。重取一遍拿权威 `id↔题面` 映射，顺手与旧档逐条 diff——这步就是**对旧记录的校验**（实测两日 48/48 逐字一致 ⇒ 「题库未换」）。
   - **收满的判据看编号连续性**：`id` 1..N 无缺号、无越界才算收全。⚠️ 收尾那几题抽中概率极低（实测最后一题连等 33 轮）⇒ **别单靠「连续 N 轮无新题」早停**（会在 47/48 处收手）；双条件——**收满目标数 or 达请求上限**（`gate_probe.py --target-count N --dump out.json`，早停只用于「不知道总量」的探索轮）。
   - **快照三件套**：`id↔题面` JSON（带来源／时刻／口径／计数／缺号）＋ 人读 md ＋ **sha256**，**抓取脚本一并入库**。以后任意时刻抽 3–4 批（≈20 题）与快照逐字 diff ⇒ 「内容未换」（与 ⑫「内容型基线」同法，比「看起来一样」硬）。
   - **另存 ≠ 搬走**：旧处那一节先判它是**同一份数据的副本**还是**另一件东西**——是本轮的扒取过程与判决（时间、方法、当时的判断）就**留着**，删了会让下游（抽样观测档／总索引／举报材料）引用断链，只加一行指针改道；确属重复副本才改成挂链（同「一件东西一个家」）。收尾同步总索引／README 与引用它的下游文件。

## ⑨·7 生态清单去伪：**矩阵号识别**（2026-10-09 实战，用户判语「有很多都是假的，默认视为矩阵号」）

同一关键词搜出来的一堆同类视频/帖子，**先分层再入清单**，否则会把引流垃圾当"生态节点"（踩过坑：把一条"私人搭建＋无限内购"视频当成"更早的商业化苗头"写进时间线，被用户当场纠正）。

**矩阵号指纹（命中两条以上即按引流矩阵处置）：**
1. **标题模板化**：无限内购／公益版／内置 GM 后台／无偿免费分享速拿／一键三连——同一批句式换号重发。
2. **跨题材套用同一模板**：同一账号同时发另外一款游戏（甚至别的品类）的同款标题 ⇒ 通用流水线，不针对目标。
3. **账号形态**：随机字符串 ID、无认证、投稿数十上百条流水、签名/简介挂 QQ 群号（引流终点）。
4. ⇒ **不入生态清单**（或单列「噪声带」）；**不接触其引流群、不下载其包**。

**反向指纹（真项目）**：简介写「仅供个人学习／不做分发／不会上传包」，且能追到仓库、持续投稿、有项目实体。⇒ **"标题党催你加群" vs "简介声明不分发"，这条对立本身就是最快的分类器。**

清单每条都要**标层**，别混排：**真创作者（可追仓库／合集）／搬运二传（转他人成果）／噪声带（引流矩阵）**——用户要的是「这一波里谁真的在做」，混排等于把噪声算成了生态。

⚠️ **「分不分发」必须逐项目实测，不能按印象归纳**：同层里三种都有——明说「不会上传包」（不分发）／开源仓库（分发，走代码渠道）／简介直挂网盘（分发）。拿「真项目简介都写仅供学习」这类圈内印象代替逐条读，会把结论写错（实测被推翻过一次）。逐条要看的就两样：**简介原句**＋**有没有下载链接**。

**新号段可当辅助筛子**：引流矩阵号 ID 密集落在 16 位新号段（实测双生系 16 个里 14 个），真创作者是 8–10 位旧号；但旧号里也有噪声（不可当铁律），只用来排优先级。⚠️ **判据里的数字同样要实测**——位数、条数这类「顺手写下的常数」最容易凭观感写错（本页初稿把 16 位写成 19 位，复算 `len(str(mid))` 才回到 16 位）；判据里的数字错，后面的人（含自己）会当事实照用。

**判「圈内人 vs 通用产线」看全量投稿的题材跨度**：拉这个账号的空间列表（`bilibili-api-ops` 的 `scripts/bili_space_wbi.py <mid>`）把所有投稿横排——作品在**十余款同代停服手游**之间跳、标题同构 ⇒ 他是「停服手游单机化」的**通用产线作者，不是本圈的人**（实测：一个被写进本圈生态的「真项目」，46 篇投稿横跨十几款游戏，做的还是目标 IP 的前作）。圈内人则是围绕**一个作品长期连载**（跨年多期进度展示）。这条决定他该进「同波对照」还是该从生态清单里剔出去。

## ⑨·8 客户端/APK 重打包痕迹（拿到样本后的第一轮只读检查）

对方给的是**装好的客户端**而不是源码时：先做 zip 清单＋字符串检索，**不安装、不运行、不联机**。

| 看什么 | 命中意味着 | 怎么取 |
|:--|:--|:--|
| **`.orig`／`.bak`／`*_decrypted` 残留** | 打包者改过文件又没清备份 ⇒ **白送一组「改前 vs 改后」对照** | `namelist()` 正则筛 `orig\|bak\|backup\|decrypted` |
| **配置文件两版 diff** | 改动能窄到几行 ⇒ 一句话说清「他动了什么」（实测：整份环境矩阵只改 3 个键） | 两版原件**逐字节入档**（哈希与包内条目一致）再 diff |
| **内网 IP 残留** | 交付包里留着开发机的局域网地址 ⇒ 存在本地服务端环节（**但不指认是谁的机器**） | 全条目 grep `192\.168\.`／`10\.`／`172\.1[6-9]` |
| **签名与权限** | `CN=Android Debug`＋无 v2/v3 ⇒ 重打包自签；**权限要按二进制 manifest 实测解析**（粗糙捞串会漏——实测一次只捞到 2 项、实际 6 项，含读写外部存储） | 解 `META-INF/*.RSA` 走 `openssl pkcs7 -print_certs`；`AndroidManifest.xml` 用最小 AXML 解析器读（`resource` 段起点的 `attributeStart` 是相对**元素结构**的偏移，别算错） |
| **官方遗产** | 包里留着官方 AppId/AppKey、开发组 Lua 作者注释、官方公告地址 ⇒ 来源与侵权面的直接证据 | `assets/*.properties`、`*.lua` 头部注释、`envir/config.json` 类文件 |

⚠️ **「搜不到」要构成结论，先证明「能搜到」**：判定「某逻辑不在客户端」前必须先确认目标文件是**明文**（拿一个已知串验证可命中），否则加密/打包会让零命中变成假结论。实测：GM 口令在客户端 0 命中，前提是 lua 明文可读 ⇒ 才敢写「GM 判定在服务端」。

⚠️ **只读检查只支持「是什么」的结论，不支持「有没有恶意」**：交付里明写**未做行为分析、未运行**，把「是否含恶意代码」留成未决——这句不是客套，是防止后人把「未发现」读成「安全」。

**端点面照上游文档逐条对（只读）**：拿上游 README 的端点清单当标尺，逐个 GET 对照自研服务端——实测 `:18080/serverlist` 有、上游同列的 `/serverstate/<id>` **404** ⇒ 结论写成「**继承的是端口与既有端点，端点面没跟全**」，比笼统的「协议同构」精确，也让「同构 ≠ 同源」多一条实证。

**错误响应体是免费的指纹**：未匹配路由统一 `404 {}`（无框架 HTML 错误页）＋ 往端点发**空 body** 回**框架原生报错原文**（例：System.Text.Json 的 `The input does not contain any JSON tokens…LineNumber: 0`）⇒ 不用猜框架版本就能坐实技术栈。⚠️ 这类请求**只 GET／只发空 body**，不构成写入。**GET 打到只收 POST 的端点同样好用**：回 `400` ＋ 框架原生报错 ⇒ 既证明该路由存在、又零写入。

⚠️ **同名不同物**：抓取目录里常混着**自家的取证清单**（自己也叫 `manifest.json`）——拿它跟站点路径比，会得出「站点删了文件」的假结论。比对前先确认：**这个文件是谁产生的**。

**说「只改了 X」必须有原件基准**：与自身旧版／上游文档比只能得出「相对变化」，得不出「仅改 X」——实测在拿到**同源原件**后，原先记的「改动面仅三个配置键」立刻被推翻（资源包下另有七个文件不同、权限被砍四项）。「仅」字必须由同源原件对照支撑，否则写成「已比对的两个版本之间，变化集中在 X」。**两包逐条对照的具体读法**（四分类／体积与压缩方式／资源清单集合差／尺寸差≠改动量的逐字节口径）见 `apk-reversing.md` §官方原包对照。

**Unity AssetBundle(`.u`) 不必装 UnityPy**：头是 `UnityFS\0`（版本 6、Unity 2018.4）时，纯 Python 就能解——手写 LZ4 block 解压 ＋ stdlib `lzma` 即可（`scripts/unityfs.py`，本 skill 已收：8B 签名/版本/两个 cstr/8B size/3×u32 `cbi,ubi,flags` → 解压 blocksInfo（含 16B 占位 hash）→ blocks/nodes → 逐块解压）。⚠️ 同一包里**并非每个 `.u` 都吃同一套解析**：实测 6 份中 4 份成功、`lua.u`/`setting.u` 的头字段读出不合常理（穷举偏移/大小端/16·32 位对调均失败）——**遇到解不开的记「未解」，别把失败当"文件损坏"**。

**判断"资源被改成什么"用「只在一边的资产清单」**：解出两个 bundle 的 CAB 段 → 扫 `assets/_game/...` 路径（正则**锚定扩展名** `.tga|.png|.mat|.prefab|.asset` 再清理，否则长度前缀的尾字节会污染集合差，同一名会被判成"一边加、一边删"）→ 集合差。若**新增项全是官方命名规范、且同时有"官方有而它没有"的条目** ⇒ 不是"往官方包里加料"，而是**整套换成另一份（更晚的）官方构建**；配合 `version.data` 资源清单计数（1074→1366）与语言表新增/缺失数，三个方向互证才写结论。

## ⑩ 交付形态：多轮溯源怎么收口

- **每轮探到东西就当场增量落档**（同一事件线追加小节 ＋ 原始群聊原话单文件 ＋ 页面内嵌 JSON／头像／截图这类附件随档留），别攒到收尾一次性写——用户中途会接着喂料，档就是他跟你对账的地基。
- **收尾交「一页纸汇总」**（用户说「可以汇总了」＝要定稿）：定性（已证）／端到端流程（每步标「谁控这一环」）／身份线索**已证｜未证分栏**／与既有档案的节点链接续 ＋ 观察项对账／用户侧下一步（本机拿不到的几格）／附件清单。深度细节留在全量档案里，汇总只做索引与结论，别把全量再抄一遍。
- **本机拿不到的环节写成「用户侧下一步」一行**（域名实名/ICP 备案主体、群内对人、昵称检索），不写成「待核」挂账；注册局 RDAP／whois 站这类本机不通的入口直接列给用户一次，不反复重试。
- **同日多层聚合＝「开张日」**：把跨层时间戳并排（域名注册日／证书签发日／新群建群日／站内公告日／首次在群里发出官网的时间），同一天凑齐几件就是这条线从「私域」转「正式运营」的分界；一条时间线讲清这点，比逐个报日期有用。
- **档案结构：案子长到多轮就该拆**（「README.md」 只做**总索引**：导航 ＋ 时间轴 ＋ 关键判据，正文别堆在里面）。按用途分目录，**编号前缀让目录顺序＝阅读顺序**：`00-判词`（一页定稿）／`10-过程账`（逐轮日志、原始聊天原话）／`20-历史档`（前史）／`30-证件`（举报文本，内部版与对外版分开存）／`40-取证`（整站抓取＋哈希清单＋截图＋工具复核件）／`50-机制附件`（流程、链路明细、题库全文）／`60-第三方核查`（他人报告与回执**只放指针＋结论，不复制正文**，避免两处维护）。操作要点：拆完**必跑 `bin/mdcheck <目录>`** 修相对断链（移动 md 会整片打断引用，含 `../` 层级要重算）；图像附件常按仓库策略不入 git，清单里注明「仅本地」；一页定稿里的附件清单同步改成本档相对路径（表格里只写裸文件名会被判成断链）。

- **用户点名一个「简单确认」时，只做他点名的那一件事**：「简单确认一下」「应该能快速验证出来 X」＝照他给的那个参照物做**一次**核对就回报，**别顺手搭工具链**（实测被一句「应该没有这么麻烦吧」叫停：为核对图标角色自己写了模板匹配脚本、还挂了后台长任务）。判据：他说的一步能走完（抓一张参照图／看一眼某个页面）就一步走完；确实要多步才写脚本，且**先回报「我打算怎么验、几步」再动手**，别闷头做。

## ⑩·5 公开面检索（用户说「最好联网搜索相关资料」时）

要的是**这个项目在公开面上什么状态**，不是随手搜两下：

1. **先搜正式名，再搜圈内口头名**：项目自己的名字（域名／群名）常常搜不到，圈子里对它的叫法一搜就中——口头名是第二轮必试项。
2. **相邻同类项目的评论区是私域项目唯一的公开出处**：同行会在别人的视频评论区互相点名（实测：某复活项目的作者在另一个作者的视频下留一句「跟隔壁 X 服比，进度如何」——那就是目标项目最早的公开痕迹）。⇒ 定位私域项目时逐个翻同期同类项目的**评论区**，比翻搜索结果有效。
3. **搜不到 ⇒ 结论是「私域产物」**：无公开介绍、无同名账号、域名零引用，与「门禁 ＋ 群文件分发 ＋ 闭源」互相印证；写成结论，不写成「没搜到」。
4. **横向对照表＝判决参照**：把同期同类项目列成表（作者／时间／形态：开源 · 离线单机 · 明确不做分发 · 联网运营＋门禁），谁开放谁封闭一目了然；生态共性（如「倒卖已经出现」）往往正好解释目标方为什么设门禁。
5. 入口用 `bin/qsearch`（多源一键）；B 站搜索走 `bilibili-api-ops`——该 skill 有「批量题材扫描」脚本（`scripts/bili_search_scan.py`）与搜索接口的 cookie/签名取舍说明，别不带 cookie 裸 curl。

## ⑬ 复查同一个站点：下架／改壳怎么读（第二次及以后来探测）

对被查过的站再探一轮时，**结论不是「打开/打不开」，而是「这几层里哪几层变了」**。按下面三份对照走，缺一份都会写错：

- **① 今日同名页 vs 归档件 hash；② 响应头（`curl -D -`）vs 上次；③ 外壳页 vs 公告页。**
- **200 不代表「还在营业」**：关闭告示页常以 `HTTP 200` 返回整页黑底文案（实测 763 B、`<title>站点已关闭</title>`、`X-Robots-Tag: noindex`），同期 80／443 已全 timeout，而业务网关（`18080`／`30400` 这类）仍在 listen。判「关站」看**正文 ＋ 逐端口表**，不看状态码。告示页正文本身往往就把口径写死了（「本服官网不再提供访问。需要绑定或咨询请通过 QQ 群联系服主。」）＝运营方把入口收回社群的**自认**，照录原文，别概括成「已停服」。
- **多条路径回「同一份、字节数完全相同」的页面 ＝ 统一换壳**：`/`、`/register`、`/tutorial`、`/feedback` 全回同一 hash 的几百字节告示页，说明有人一次性铺了一张关闭页，**不是四个页面各自坏了**。逐页分别描述＝把一次动作写成四次故障。
- **同尺寸不同 hash ＝ 只改了文本片段**：抓下来 `diff` 定位（实测同为 6782 B，改的是 `<title>` 与几个 meta）。「改了标题」这类结论只能靠逐字 diff 得出，别拿肉眼比页面像不像。
- **去索引是单独一层证据**：响应头 `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet, noimageindex` ＋ 页面内 `<meta name="robots">` ＋ googlebot／bingbot 分条 noindex。命中就写「**有意识地降可见度**」，与藏群、改名同属一条动作线——**别写成「网站坏了」**。
- **`<title>` 里的品牌词被替换 ＝ 改名／去敏**：拿功能页（绑定页、首页）的 title 与归档件比。「产品名 → 无意义代号」是标准动作，能解释为什么后面搜不到了。
- **外壳 ≠ 公告**：告示页写「站点已关闭」，而公告页（`/notice.html` 类）仍是开站那几条、没有关站公告 ⇒ **对外表述有两套**。引用时以**公告正文**为准，告示页只当「他做了这个动作」的证据，别把告示当选事人的正式声明。
- **判「服务还活着」只看业务面**：业务 API 抽样（能取到数据／题面／状态字段）＋ 网关端口可连。两者都在 ⇒ 写「**外壳关、服务跑**」；两者皆无才谈「服务停」。外壳页、主页、检索可见度**都不算**服务健康度。

## 坑

- **探测第三方接口只做「无副作用」的调用**：想弄清接口的校验顺序（先查账号还是先查群成员），用**不存在的账号**发一次请求读报错即可（实测回「账号不存在，请先到官网答题注册」⇒ 账号校验在前，该接口当不了群成员查询器）；**绝不为了探测去注册／绑定**——那是真实副作用，先问用户。
- **用户要「确认流程」时，交付端到端流程文档**（入口 → 注册闸 → 分发渠道 → 安装 → 连线 → 运行期），每步标「谁控这一环」＋实测依据，末尾附「判决要素（只列结构事实）」；他要的是结构判据，不是人身结论——别越界去挖具体是谁（用户一句「只需要确认流程，就可以判决了」就是收手信号）。
- **execute_code 里解析 GitHub/Gitee 的 JSON 会莫名抛错**：响应体带控制字符时 `json.loads` 报 `Invalid control character` → 用 `json.loads(txt, strict=False)`，或 `curl -o file` 再读文件；中文查询参数必须 `urllib.parse.quote()`，别手拼 URL。
- 群聊里玩家自解的因果（「申请不秒进是 QQ 等级低」）当**线索**看，别当事实写进结论；没有证据的直接标「未采信」。
- **别把两种「属地」当同一把尺子**：平台的 IP 属地＝发布/登录时出口 IP 的归属（常只能在页面读数，接口字段是空的）；域名 registrant 的地址＝实名登记地址（多数只到省级）。两者不一致，只能写成「没有证据把两个身份合并」，**不能写成「确定不是同一人」**。要互证就去另一个平台找该主体的 profile 地址（独立来源才算数）。
- 溯源写进档案时，结论栏要能脱离本次事件读懂：写「协议同构/后端语言/域名注册日/拿不到哪几项」，不写「今天查了一下」。

## ⑪ 顺链下钻：项目 → 上游 → 方法论层

用户说「简介里还有一些东西能细挖」时，意思是：**每一轮拿到的新链接都是一跳，把外链当入口继续走**，别停在「这条视频讲了什么」。

- **视频简介／评论区里的外链＝下一跳入口**：仓库地址、网盘、QQ 频道号、开发日志群。顺过去用 GitHub API 读 README／topics／建仓与末次 push 时间／license／star-fork，把「作者是谁、这项目长什么样」补成一格；简介里的技术自述（用了什么插桩／重定向／网关方案）是判「同波不同路」的直接材料。
- **同一作者的仓库列表常同时躺着「某个具体作品的复原工程」和「一套通用方法论／工具仓库」**——后者解释**为什么同一时段突然密集冒出同类项目**（可复用流程 ＋ Agent 自动执行 ＋ token 消耗），也解释技术栈为什么趋同。翻目标圈的几个作者，找到这类方法论仓库是最高价值的一跳。
- **用方法论仓库自己的分类法给这一波项目归类**（实测三路线）：**复原服务端**（重写服务端让客户端以为还在官方服）／**改造客户端**（把服务端逻辑塞进客户端做单机）／**重做客户端**（只提资源重做展示）。每个项目对号入座后，横比「谁开放谁封闭」一目了然，比逐个描述项目清楚得多。
- ⚠️ **同一技术栈 ≠ 同一个人／同一个项目**：目标方与上游同语言同框架（如都用 .NET）只能推出「同方法论来源、同技术圈层」，写结论时别合并主体。
- ⚠️ **圈内「不分发」是常态**：同类项目的简介常写「只做演示，不会上传包」「不做游戏分发」。目标方反其道而行（网盘／群文件分发），**这条差异是判「运营」而非「留念」的关键证据**，值得单独写一行。

## ⑫ 取证固化与举报备料（用户说「下一步，举报」时）

用户决定走这步时，你交的是**材料与门路**：材料备齐、渠道列清，**提交由用户本人做**（实名要求因渠道而异，不代提交、不代签署）。

**第一步永远是固化证据**（对方随时可能清档／换域／删链）：

```bash
base=workspace/records/<事件>/取证-<YYYYMMDD>; mkdir -p "$base"
for p in / /index.html /register.html /bind.html /assets/js/config.js /api/quiz; do
  fn=$(echo "$p" | tr '/' '_')
  curl -sS -m 25 -D "$base/$fn.headers" -o "$base/$fn" -w '%{http_code} %{size_download} %{content_type}\n' "http://<host>$p"
done
```

- 关键端口指纹（如列表服务 JSON）也存一份；再逐文件算 sha256 生成清单。
- 清单列：目标路径 ／ HTTP 状态 ／ 字节数 ／ sha256 ／ 抓取时间（时间走 `bin/now`，＋8）。
- **sha256 清单的第二个用途：跨批次当「有没有动」的基线**。下次重取同一批文件，逐文件比 hash——全等 ⇒ 只能声明**两次抓取之间**静态面未变（写有界句，别外推成「自某日以来未改」，那要有更早的快照才敢说）；有任何一处变了 ⇒ 先看变的是哪个文件，那里往往就是最近的运营动作。这条比「公告更没更新」可靠，也顺手回答「它还在不在运营」。
- 截图、页面内嵌 JSON、头像这类附件**全部收进同一个取证目录**，别散在多个目录里。
- **抓存页要出「可视证据」时，本地渲染补截图——但必须标成渲染件，不能冒充原截图**：`python3 -m http.server` 以抓存目录为根 → Playwright 打开对应 `.html` → `full_page=True` 出图 → 与现行页配成前后对照（`页面存档渲染-<页名>-<抓存日>抓存.png` ／ `现行-<页名>-<今日>.png`）并进同一取证目录、同进 sha256 清单。⚠️ Playwright 报 `Executable doesn't exist ...chrome-headless-shell-<版本>` 时不要重装：`find /opt/hermes/.playwright -name chrome-headless-shell` 取实际那份，`launch(executable_path=...)` 指过去即可。⚠️ **样式与图片没随抓取时渲染必然是降级版**（实测 css/js 全 404、导航退化成文字链接、图片只剩 alt 文本）⇒ 落档口径写死「**文字内容可作证据，版式不可作版式证据**」；它即便成了某页面的唯一可视证据，也照样这么标。
- **清单里「同 sha 不同名」＝假件，登记与复查都要查一次重**：一份标作「官网首页截图」的图，sha256 与同批「题库第 20–39 题截图」逐字节相同（同尺寸 887×1920）⇒ 真身是题库，该页原图**从未存在**，此前所有「有原件」的读法一并作废。规矩三条：① 入清单前按 sha 去重，同 sha 不同名当场核图再决定标什么；② 每轮复查顺手对清单内部做一次 sha 查重（按前 12 位分组），命中按 ⑥ 只增不改补更正条；③ **拿「原图／原件」下判断之前先看图对不对标**——文件名是上一轮的人标的，不是证据本身。
- **抓完做一次「引用 vs 归档」对账**：正则抽出已入档 HTML／JS／CSS 里引用的同源路径，与归档清单比 ⇒ 补齐漏取项（页面引用的 js/css 最容易被漏：实测一个功能页取了、它引的 `*.js` 两批都没取）。补完这批，才敢在清单上写「取证完整」。
- **内容型基线同样能答「有没有动」**：题库／文案这类内容，拿少量**只读抽样**与既有全量逐条比（题面逐字），报「覆盖 N/M、逐字一致 N、不一致 0、超出范围 0」⇒ 「**内容未换**」这种结论比「看起来一样」硬，且与静态面 hash 基线互补（hash 管文件、抽样管内容）。
- **用户从对方分发渠道取回的本体（客户端 APK／教程录像／说明文本）＝另一类材料：进来先隔离**——移出档案目录 → `workspace/quarantine/<YYYYMMDD>-<案子>-样本/`（自带 「README.md」：清单＋哈希＋口径），根 `.gitignore` 加 `workspace/quarantine/`（几百 MB 的本体默认不受任何 ignore 规则保护，实测以 `??` 裸奔，下一次 `git add` 就进库），**档案里只留哈希与结论**；不安装／不运行／不联网／不外传。只读静态检查配方与工具见 `apk-reversing.md` ＋ `scripts/apkscan.py`。这类样本能把「客户端里到底嵌了什么」从「用户侧下一步」直接变成结论（实测：包名沿用上游作者命名空间、Debug 签名、内嵌自建服务地址＋打包者内网 IP）。清单**保留原始 mtime 并按原始时间序排**（一次取回的若干文件常跨周，时间序本身就是分发链时间线）；出现 **0 字节文件**时，内容可能只在**文件名**里（群文件常见「标题即全文」）——按线索登记，**别当正式公告**写进结论。

**证据升级：站内文案批量查重（只举一句不够硬）。** 站点搬素材时**图文一起搬**——图像看元数据（⑦），文字要做批量比对：

1. 抓站内长文案（角色介绍数组、世界观／玩法段落）→ 按标点切句，每段取 2–3 条 ≥8 字的片段。
2. 打目标 wiki 的 MediaWiki API（bwiki 类站点免登录可用）：
   ```bash
   curl -sS 'https://wiki.<站点>/<wiki>/api.php?action=query&list=search&format=json&srlimit=5&srsearch=<片段>'      # 检索词条
   curl -sS 'https://wiki.<站点>/<wiki>/api.php?action=query&prop=revisions&rvprop=content&rvslots=main&format=json&titles=<词条>'  # 取词条源文本
   ```
   判定用**字面子串**（`frag in text`），别用模糊相似度——相似度会给出无法举证的「疑似」。
3. 汇报格式＝**命中率 ＋ 一条单句铁证**（实测：14 条角色介绍 8 条逐字命中，另附一条一字不差的整句）。**未命中 ≠ 原创**——片段选取与词条覆盖都会影响结果，只能写「本方法未命中」。
4. 产出直接喂举报材料的「文字素材」一条：由单例升级为批量比对结论，硬度完全不同。

**举报对象分层**（一层一行，别混成一句）：

| 层 | 对象 | 处置／期望 |
|:--|:--|:--|
| 社群 | 群（群文件/群相册是分发口） | 群举报（侵权/传播盗版）→ 解散/限制，**最快见效** |
| 分发渠道 | 网盘分享（分享者 uid 已记录） | 网盘举报 → 链接失效 |
| 站点/服务 | 域名（注册商）／源站 IP／开放端口 | 注册商侵权投诉；境外机房与 Cloudflare abuse **期望值低** |
| 权利人 | 研发方／原代理方 | 有强制力，但对已停服 IP 动力低 |
| 监管 | 版权局／网信办／不良信息举报／扫黄打非 | 适合不便暴露身份时，多要实名 |

- **口径三段式**：① 事实（未授权服务端 ＋ 分发官方资产 ＋ 提供联网服务 ＋ 运营社群）② 证据（附文件与哈希）③ 请求（停止侵权／下架／依规处置）。
- **文本出两版**：内部版（三段式 ＋ 口径提醒／见效预期／别误伤开源作者）留给用户对账；**对外版只保留可直接发送的正文与平台短文案，剥掉全部内部备忘**——用户会整份转给朋友或直接粘进举报框，内部提醒外流等于把策略也交出去。
- **用户说「这份分析也可以整进对外材料」时，交「附页」而不是把分析稿搬过去**：附页＝**只摆事实、不写评价**的对照件。① 分层用**类目＋判据**，**不列非涉事方**（真创作者／开源作者那几层只描述形态，并明写「为避免误伤，本附页不列非涉事项目方的账号信息」）——要处置的线索才落到具体账号 ID；② 每条给**可复核字段**（账号 ID／原标题／日期／读数时间）并写明采集口径（哪个接口、多少关键词、什么时刻采的）；③ 末段用「本次举报仅针对 X，其他层不在范围内」把边界钉住；④ **交付前 grep 自检**：内部标记（内部自称／内部备忘／档号／节号）与所有非涉事方名字，命中就删——对外文本里出现内部编号，等于把「背后有一套档案」一并交出去。
- **收件入口用公开可查的，别臆造邮箱**：官方客服邮箱常写在用户协议／隐私政策条文的联系方式一节（抓那个页面 grep `@` 与「客服邮箱」），另有客服中心工单页与公开客服电话；找不到就写「用户自行查官方入口」，不编地址。
- **用户甩来一个邮箱时，先查它是不是公开可查的**：搜不到引用 ⇒ 写「用户手上／圈内的直连地址」（常是商务／BD 类信箱，未必走侵权流程），**照用为主收件人，但同时在文本里列一个公开可查的客服邮箱作为建议抄送**——双通道保到达，且抄送项本身可核；文本里要标清哪个是用户给的、哪个是官方公开的，别让后代分不清来源。
- **保护用户**：① 提交由他本人做；② **别在同一圈子宣告**——用户在圈内常有公开身份，举报人暴露会招反弹，举报用账号／邮箱与圈内身份解耦；③ 见效预期先说清（平台线 ＞ 权利人线 ＞ 监管线）；④ **口径别误伤同源的开源作者**——目标方的资源／协议继承自某个开源项目时，只指向目标方自己的未授权运营与分发。
- **举报节奏与发信身份**：需要多封举报时**间隔开**（同一天抵达像协同行动，反而不像各自独立的举报）；发信邮箱与圈内身份解耦——用与圈子无关的地址，别用与圈内身份绑死的邮箱（用户会自己得出这条：「选某常用邮箱好像把自己走窄了」）；把用户的定位照写进材料（例如他只肯以**个人举报**署名，就别替他升格成代表社群）。

**凭据与社交账号收口（站点把用户的密码／社交账号收进去时，这是独立的一条结论线）。** 用户会自己把它拎出来说「我先把这个问题统计一下」，交付要能直接当那一节用：

- **判「恶意 vs 无经验」的尺子在凭据处理，不在域名新老、也不在自动化程度**：对照样板＝**不接触密码**（发临时密码、由第三方身份系统强制重置）＋登录域是可信方域名；反例＝自己收密码、明文传、还额外要真实社交账号。**同样自动化，凭据一破线，性质就变**。
- **两句话口径缺一不可**：①「无证据表明它在盗号／有恶意」（无恶意样本情报、无收费入口、更像无经验搭台）；②「但流程形态具备盗号链条的全部要素」（明文收割凭据 ＋ 收集真实社交账号 ＋ 服务端能判定账号归属某群 ⇒ 手里有名单 ＋ 存储方式不可验证）。可举报的写法是「**未授权运营 ＋ 明文收集凭据 ＋ 收集社交账号**」，不是「它在盗号」——省第一句＝诬指，省第二句＝风险没写清。
- **风险面按行统计**（各行一条、各配实证）：明文传输（哪个端点、什么字段）／强制交真实账号（字段＋必须属于某群）／换绑不校验原账号（知道账号密码即可改绑）／服务端具备成员名单校验能力／**密码存储方式不可验证**（这条不可验证本身就是风险点）／规模（两侧群人数或注册量级）／弱口令习惯（最低长度要求）。
- **门禁站点里的「不可验证项」要单列**：闭源 ＋ 个人服务器 ⇒ 无法确认是否哈希、是否复用；写「无法验证」，别写成「一定明文存」。

**材料里出现「用户的朋友／同行」时的两条纪律**：

- **只落可核的公开事实**：域名、公开项目名、公开面时间线（这些本来就查得到）；**个人标识（真名、账号 handle、个人名片页、私人邮箱）一律不落档**——不写、不推测、连「边界禁令」里也不举实例。
- **顺手拿到「正规做法」的样板就单独记一行**：同行自述的合规流程（不碰密码／身份托管／登录域可信）是判目标方的现成标尺，比抽象讲「应该加密」有力得多；但**对方的站点只做公开面轻探**（DNS／CT／首页／TLS 有无），不继续下探——那是别人的地方，要问就让用户自己去问。
- **转发面自检**：把分析原文转给第三方前**剥掉内部编号**（节号、档号）——内容没问题，**编号本身会暴露「背后有一套档案」**；这类提醒说一次就够，别反复念。
