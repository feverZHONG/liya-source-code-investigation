# 生产前端包取证（SPA / webpack 分片）

> 场景：**只有线上服务、没有源码**，要判「这产品有没有某功能／下一步要做什么商业动作」；或**复核第三方的前端 diff / 监控报告**。
> 与内容收割的分界：那边目标是「把正文／字段拿出来」，这边目标是「从代码形状推出产品能力与商业动作」。产物是判读，不是数据。

## 一、抓入口，先固定三个锚

```bash
curl -sS -m 30 -A '<正常桌面 UA>' https://<host>/ -o index.html
sha256sum index.html
grep -oE '(main|vendor)[^\"]*\.(js|css)' index.html | sort -u
grep -oE 'name="commit-id" content="[^"]+"' index.html
```

HTML 哈希、脚本名、仓库里写的 commit 号＝**「这是哪一版」的唯一硬锚**。截图／OCR／转述里抄来的哈希一律不可信（漏位、O/0、f/ff 混），要引用就先回线上重算一次。

## 二、从主包取版本号

主包（几 MB 的 `main.*.js`）里搜构建期注入的常量，通常是 `appVersion:"x.y.z"`、`clientVersion:"…"`、`commitId:"…"`。
**判据**：版本号动不动，比「页面看着不一样」可靠得多——前端改版一定动它，动了才说明这次是真的发版。

## 三、把懒加载分片全拉下来（关键一步，别只看主包）

主包里找打包器的 URL 工厂，形如：

```js
h.u=e=>"static/"+(({27390:"prism-m-r",…})[e]||e)+"."+({10025:"0c91c3ae7d",…})[e]+".js"
```

第一张表是 id→名字，第二张是 id→hash。正则抓第二张，拼 `base + static/<name|id>.<hash>.js` 并发下载：

```python
pairs = dict(re.findall(r'(\d+):"([a-f0-9]{6,12})"', m.group(1)))   # m = 上面那段映射表
# ThreadPoolExecutor(max_workers=16) 并发 GET；已存在且非空就跳过
```

实测规模：606 个分片 ≈ 10.5 MB、十几秒到两分钟。**不下分片就下结论＝只看封面判书**。
- 命名分片（`katex`／`prism-*`／`mermaid*`／`web-tts` 这类）常 404——异路径或只出 CSS，**不是失败**；与本结论无关就别追，写进「未核」即可。

## 四、分片到手后能稳定挖出的六类事实

| 类别 | 锚点 | 用途 |
|:--|:--|:--|
| 接口清单 | `"(/api/v\d/[A-Za-z0-9_\-/]+)` | 能力面清点；有没有新服务端域一眼看出 |
| 错误码枚举 | `\[[a-z]\.[A-Z_]+=(\d+)\]="([A-Z_]+)"` | 服务端能力的硬名单——**新功能常先有错误码、后有界面**；老码还能证伪「以前完全没有 X」 |
| 埋点事件 | `name:"([\w]{3,40})",message:"([^"]{1,40})"` | 产品关注点；运营位复用了哪个老埋点名，就说明它搭的是既有通道 |
| 服务端配置域 | `scope:"([a-z_]+)"`、`getLatestFeature\("(\w+)"\)` | 哪些策略**不发版就能改**（模型清单、文案、上限、开关） |
| schema 校验函数 | 找 `typeof x.title==="string"` 那类校验块 | 字段全集与边界，比 UI 更能说明「服务端能下发什么」（图片 tint、按钮组、关闭方式） |
| 自定义协议/深链 | `dsaction://`、`open_url` | 站外跳转/购买引导的管道在不在 |

## 五、判据纪律（最值钱的一节）

1. **短词先怀疑 vendor 包**：`coding` 全来自 `encoding/decoding`、`Plan` 来自 `airplane`——命中动辄几百次的那个 3 MB 分片基本是 vendor。先看「命中集中在哪个文件、那文件是什么」，再谈结论；必要时改用长词或加词边界。
2. **中文文案只认主包**：语言分片装的是别的语种，主包里才有中文 i18n。**「中文关键词零命中」不等于功能没做**。
3. **检索面写全**：「主包 + N 个分片内零命中」，并列出没拉到的分片——不写「不存在」。
4. **代码里有 ≠ 已生效**：能不能给用户看见取决于服务端是否下发。结论必须带这一层，并顺手写「生效了会长什么样」。
5. **管道 ≠ 商品**：有弹窗、有按钮、有站外跳转，只证明**触达管道铺好了**；不证明已经开卖。别把「准备卖」写成「在卖」。
6. **第三方报告当线索，逐条核，出偏差表**：口径可能整个反（「取最晚」被写成「取最靠前」）、键名可能错、结论可能夸大（「完全没有」）。核完再引用，别整段转述。
7. **拿不到旧版包时**：只断言「现包里有什么」，报告的旧版差异标注为「未复核」；新旧对照要用同一把尺子（同一条正则、同一个关键词表）。

## 六、落档与复用

- 快照 JSON（版本、commit、HTML 哈希、关键词计数、接口清单）入库；整包 js / html 与截图留本地并 gitignore（体积大、可重取）。
- **写成一条命令**，下次对比只跑一条：`snapshot`（全表）/ `status`（一行）/ `--save`（连证据一起落盘）。手敲一遍 grep 的活不叫资产。
- 档案末节写**观察信号**：下次抓到新版先看哪三个字段（新档位、周期性重置、跳转目标），比堆一堆结论有用得多。
