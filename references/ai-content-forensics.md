# AI 生成占比鉴定（无源码：判断一个站点／项目「有多少是 AI 写的」）

> 触发：用户问「这网站／这项目有多少是 AI 写的」「是不是 AI 做的」。
> 场景：手上只有**能观察到的产出**（前端文件、站内文案、接口行为、运行中的服务），拿不到服务端源码。
> **交付形态固定三件**：① 逐模块判定表（模块｜判定｜判据｜置信度）② 占比估算（标「估算、非精确」）③ 可证伪点。**不要只给一句「看起来像 AI」。**

## 先说边界

这是**产出物指纹鉴定**，不是源码鉴定——结论每条都要挂置信度，并在结尾列「怎样才能证伪我」（拿到源码／作者自述；或做对照实验：让 AI 按同模板现场生成一份，比对结构重合度）。样本太少（两三个文件、几句文案）时只写「疑似」，不写占比。

## 判据一：注释分布指纹（最便宜、最硬的一把）

逐文件统计「注释数／中文注释数／含日期注释数」，看**注释分布是否均匀**：

```python
import re
for f in files:
    src = open(f, encoding='utf-8', errors='replace').read()
    if f.endswith(('.js', '.ts')):
        cs = re.findall(r'//[^\n]*', src) + re.findall(r'/\*.*?\*/', src, re.S)
    else:  # html/css
        cs = re.findall(r'<!--.*?-->', src, re.S) + re.findall(r'/\*.*?\*/', src, re.S)
    cn = [c for c in cs if re.search(r'[\u4e00-\u9fff]', c)]
    dated = [c for c in cn if re.search(r'20\d\d[-/年]\d{1,2}', c)]
    print(f, len(cs), len(cn), len(dated))
```

**读数规则：**

- **骨架文件 0 注释、出事过的文件扎堆解释性中文注释＋修复日期** ⇒ 「**AI 一次成型 ＋ 人只在翻车处动手**」。实测分布就是这个形状：首页／注册页／主 JS 全 0 条注释，而注册脚本 32 条、绑定页 10 条（含两个日期）——人只在被用户反馈逼到的地方留手。
- 反过来，**全站注释均匀密集**更像人写的长期项目；**全站零注释但功能完整**更像一次生成后没回头。
- 注释的**内容**比数量更值钱（见判据四）。

## 判据二：内容逐字查重（分「生成」与「搬运」）

长文案（角色介绍、世界观、FAQ）拿公开数据源（wiki 类）做**字面子串比对**，不要用模糊相似度——相似度给不出可举证的结论。配方见 `service-attribution.md` ⑫ 的批量查重一节。

- 命中率高 ⇒ 这一块是**搬运**，不是 AI 生成也不是自写——它是独立的一类，占比表里单列。
- 未命中 ≠ 原创（片段选取与词条覆盖都会影响），只写「本方法未命中」。

## 判据三：框架默认错误透出（「没打磨」指纹）

把 `System.Text.Json … LineNumber: 0 | BytePositionInLine: 0`、ThinkPHP 的 `controller not exists:…` 这类**运行时原始报错直接甩给终端用户**，说明错误处理没做过——同属「生成后没回头」，也是技术栈指纹（见 ④ 协议指纹）。

## 判据四：人写痕迹**反向**认（只有被真实反馈逼出来才会写的话）

不要用「写得像人」这种印象判据；认这几类句子，它们**在缺少真实运行反馈时不会被写出来**：

- 自述修复史：「原实现用了 async/await + fetch，这在老浏览器里是语法错误」「提示显示在页面最底部，手机上根本看不到」「**线上日志证明请求确实发出去了**」
- 带日期的补丁标记、按用户反馈改过的超时／配额／重试逻辑、反馈表单里收「机型／时间／IP」这类排障字段
- 教程里对模拟器、显卡、权限的实操颗粒度（不同设备给不同建议）

⇒ 这些算**人补**；「AI 一次成型 ＋ 人补丁」的组合里，人补的部分通常很小（实测约 15%），且**集中在让流程跑通，不在内容**。

## 判定表与画像模板

| 模块 | 常见判定 |
|:--|:--|
| 页面骨架／CSS／JS 骨架 | AI 生成（高置信）——零注释、结构规整、一次成型 |
| 题库／数据集类内容 | AI 生成（高置信）——字段化模板、不校歧义（见 `service-attribution.md` ⑨·5 第 4 条） |
| 角色／世界观长文案、素材 | 搬运——逐字命中公开数据源 |
| 兼容层与业务修补 | 人写（高置信）——判据四的句子 |
| 协议／端口约定 | 复用上游实现（既非 AI 也非自写） |
| 错误处理 | AI／新手味——框架默认报错外泄 |

占比表按**产出体量**给四个数（AI 生成／搬运／人写／复用），例如实测一组 ≈55%／25%／15%／5%。

**画像一句话模板**：**「AI 搭台 ＋ 人工补丁 ＋ 公开资料填充」**——骨架与数据集是 AI 一次成型件，人只在实际翻车处动手，内容整段从公开资料搬。⇒ 解释力在于：**它为什么看着像官方站、一深问就露底**。

## 同族错误提醒

- **内容深度 ≠ 人肉深度**（与 SKILL.md 最高铁律同族）：题面／文案看着专业，只能说明数据源够肥，证明不了作者懂行。
- 别把「像 AI」当结论词用；每条判定落到**可复算的操作**（注释计数、逐字命中、报错原文）上。
- 第三方（同伴 AI／外部评审）若已就同一对象下过「是不是 AI」的判断，**先复核它引用的那几条证据再决定采纳**——它常只看了你发过去的一片（见 `delegation-and-verification` §八）。
