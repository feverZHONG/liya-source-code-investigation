# 源码调查 · 踩坑与案例

> 从 SKILL.md 拆出（2026-09-04 拆薄）。

## 踩坑

1. **README 描述词 ≠ 项目功能形态**：某项目 README 写「前端毛坯房」+ 语言 TypeScript，实际是完整 TS 服务端（19 模块/95 测试/抽卡概率表）。**语言标签和自嘲式描述都不能定性，必须 clone 看源码结构。** 开源项目功能面进化快，旧判断过几个月要复核
2. **⚠️ 修正（2026-08-12）：「简化处理」是速通版没错，但「完整版功能全」同样不能证明作者懂机制**——同一作者两条线（嵌入式速通版 vs 独立完整版）是**工程路线差异**，不是作者水平差异。完整版功能全很可能是 AI 按数据文件生成的（先查 `Generated by` 痕迹），不能反推作者认知上限。旧版「找到完整版再下结论」的表述作废
3. **付费/商业化逻辑出现 = 风险定性升级**：调查私服/灰色项目时，源码里出现抽卡概率表/成本结算/氪金道具逻辑，商业化可行性判断要比之前高——记入风险盯点（注意：这部分可能是 AI 数据搬运，作者意图是「研究」不是「运营」，商业化落地仍需作者本人投入）

## 档案去向

- 分析结论：`workspace/records/{事件}/源码调查-YYYY-MM-DD.md`（结构：一句话结论 → 技术解剖 → 数据实测 → 结论修正 → 复核方式）
- 事件轻量索引（record-officer-daily/events/）补「后续补充」段，写明新证据/意味着什么/与旧判断关系
- 与事件档案相关 → 关联原事件文件；纯调查 → 独立档案 + INDEX 登记
